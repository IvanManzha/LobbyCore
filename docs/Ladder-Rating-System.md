# Ladder Rating: percentile-based система для турниров переменного размера

Документ описывает единственную актуальную систему соревновательного рейтинга (Ladder) в турнирном приложении. Размер турнира **не фиксирован**: в одном турнире может быть 8 участников, в другом 15, в третьем 30. Поэтому система построена на **относительном результате** (процентиль / доля обойдённого поля), а не на фиксированных очках за места.

**Важно:** DNA-система существует отдельно и не переопределяется. DNA = skill; Ladder = competitive progression.

---

## 1. Основная идея Ladder Rating

Ladder Rating отвечает на вопрос:

**«Насколько успешно игрок выступил в турнире относительно ожиданий и относительно размера поля?»**

Используются не фиксированные очки за места, а относительные величины:

- **percentile** — доля участников, которых игрок обошёл;
- **expected percentile** — ожидаемая доля по силе состава (DNA);
- **actual percentile** — фактическая доля по месту в турнире.

| Система    | Роль                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| **DNA**    | Skill: аналитическая оценка силы по генам и матчам                             |
| **Ladder** | Competitive progression: турнирный прогресс, выступление относительно ожиданий |

---

## 2. Когда обновляется Ladder

Ladder обновляется **один раз после завершения турнира**, не после каждого матча.

- Итоговое место игрока/команды определяется по результатам турнира (таблица очков турнира).
- Затем для каждого участника считается изменение Ladder по формуле ниже.

**Правило:** 1 турнир = 1 обновление Ladder.

---

## 3. Базовая формула обновления

После турнира для каждого игрока:

```
DeltaLadder = K_tour * (ActualScore - ExpectedScore) + Bonus
Ladder_new = clamp(Ladder_old + DeltaLadder, LadderMin, LadderMax)
```

Где:

- **Ladder_old** — рейтинг до турнира;
- **Ladder_new** — рейтинг после турнира;
- **ActualScore** — фактический результат в относительной шкале (0..1);
- **ExpectedScore** — ожидаемый результат в относительной шкале (0..1);
- **Bonus** — небольшой бонус за личный performance (опционально);
- **K_tour** — вес турнира (20 / 30 / 40).

---

## 4. ActualScore: относительный результат (процентиль)

ActualScore **не** считается через фиксированные очки за место. Он считается как доля обойдённых участников.

Если:

- **place** — итоговое место игрока или команды (1, 2, 3, …);
- **N** — число участников/команд в турнире;

то базовая линейная формула:

```
ActualScore_linear = 1 - (place - 1) / (N - 1)
```

Смысл:

- 1 место → 1.0
- Последнее место → 0.0
- Остальные места — пропорционально доле обойдённых.

**Примеры:**

- Игрок 1-й из 8: `ActualScore = 1.0`
- Игрок 4-й из 8: `ActualScore = 1 - 3/7 ≈ 0.571`
- Игрок 4-й из 15: `ActualScore = 1 - 3/14 ≈ 0.786`

Таким образом, 4 место из 15 объективно ценится выше, чем 4 место из 8.

### 4.1. Нелинейное усиление топ-мест (gamma)

Чтобы победа и топовые места ощущались сильнее:

```
ActualScore = (1 - (place - 1) / (N - 1))^gamma
```

- **gamma = 1.0** — линейная шкала.
- **gamma = 0.7** — более «соревновательная» шкала (рекомендуемый старт).
- **gamma = 0.6** — топы ещё ценнее.

При N=1 формула не определена; в коде обычно возвращают 1.0.

---

## 5. ExpectedScore: ожидаемый относительный результат

ExpectedScore — это не «ожидаемое место в штуках», а **ожидаемый процентиль** в поле.

Алгоритм:

1. До турнира оценить силу каждой команды/игрока (например, среднее DNA по составу).
2. Отсортировать участников по этой силе (сильнейший — 1-й).
3. Получить **expectedRank** для каждой команды/игрока.
4. Преобразовать в относительный ожидаемый результат:

```
ExpectedScore = 1 - (expectedRank - 1) / (N - 1)
```

- Сильнейший по ожиданиям → ExpectedScore близок к 1.
- Слабейший → близок к 0.

Система сравнивает **фактический** relative finish (ActualScore) с **ожидаемым** (ExpectedScore).

---

## 6. Почему не фиксированные очки за места

Схема вида «+10 за 1 место, +8 за 2, +6 за 3, +3 за участие» создаёт проблемы:

1. Не учитывается размер турнира: 3 место из 8 и 3 место из 20 получают одинаковую награду.
2. Участие само по себе даёт плюс — рейтинг растёт за присутствие, а не за результат.
3. Лидеры могут «фармить» Ladder за счёт регулярности.
4. Плохо масштабируется на разные форматы (8 / 15 / 30 участников).

**Percentile-based система решает это:**

- Место оценивается в контексте размера поля.
- Очки не задаются вручную по таблице мест.
- Результат сравнивается с ожиданиями (ActualScore − ExpectedScore).
- Система автоматически масштабируется на любой N.

---

## 7. Bonus (опционально)

Bonus — мягкая корректировка за личный performance, не основной фактор.

Примеры:

- `Bonus = beta * (normalizedPerformance - 0.5)`, с ограничением по модулю (например ±5).
- На первой версии допустимо: **Bonus = 0**.

Рекомендуемые диапазоны: beta = 6–8, Bonus в пределах от −5 до +5.

---

## 8. K_tour — вес турнира

Разные турниры могут иметь разный вес:

| Тип турнира        | K_tour (пример) |
| ------------------ | --------------- |
| Weekly / небольшой | 20              |
| Обычный            | 30              |
| Крупный / финал    | 40              |

K_tour определяет, насколько сильно один турнир меняет Ladder.

---

## 9. Итоговая логика обновления (шаги)

Для каждого игрока после турнира:

1. Определить **place** (итоговое место) и **N** (число участников).
2. Посчитать:
   - `ActualScore = (1 - (place - 1) / (N - 1))^gamma`
3. Определить **expectedRank** по силе поля (DNA / состав).
4. Посчитать:
   - `ExpectedScore = 1 - (expectedRank - 1) / (N - 1)`
5. Посчитать:
   - `DeltaLadder = K_tour * (ActualScore - ExpectedScore) + Bonus`
6. Обновить:
   - `Ladder_new = clamp(Ladder_old + DeltaLadder, LadderMin, LadderMax)`

Реализация: [LadderService.js](../src/backend/services/LadderService.js).

## 10. Примеры для разного размера турнира

### Пример A: турнир на 8 участников, 3 место

- Linear: `ActualScore = 1 - 2/7 ≈ 0.714`
- С gamma=0.7: `ActualScore = 0.714^0.7 ≈ 0.77`

### Пример B: турнир на 15 участников, 3 место

- Linear: `ActualScore = 1 - 2/14 ≈ 0.857`
- 3 место из 15 ценится выше, чем 3 место из 8 — формула это отражает автоматически.

### Пример C: апсет — ожидаемо 7-й из 15, занял 2 место

- ExpectedScore = 1 - 6/14 ≈ 0.571
- ActualScore = 1 - 1/14 ≈ 0.929
- Разница положительная → Ladder заметно растёт.

### Пример D: провал — ожидаемо 2-й из 8, занял 6 место

- ExpectedScore = 1 - 1/7 ≈ 0.857
- ActualScore = 1 - 5/7 ≈ 0.286
- Разница отрицательная → Ladder заметно падает.

---

## 11. Участие без автоматического плюса

Не начислять положительные очки **просто за участие** («+3 за то, что пришёл»).

Причины:

- Рейтинг должен расти за результат, а не за присутствие.
- Иначе топы фармят Ladder за счёт количества турниров.
- Участие отражается через relative finish: последнее место даёт низкий ActualScore и при высоком ExpectedScore — минус.

При необходимости можно ограничить максимальный отрицательный delta, но не вводить гарантированный плюс за участие.

---

## 12. Поведение Ladder во времени

- Ladder накапливается от турнира к турниру.
- Отражает прогресс игрока во времени.
- Остаётся относительным и честным при разном N.
- Не зависит от фиксированного числа участников.

### Сезонность и soft reset

Между сезонами можно применять мягкий сброс, чтобы вершина не «застывала»:

```
Ladder_newSeason = Base + 0.5 * (Ladder_oldSeason - Base)
```

Пример: Base = 1200. Игрок с 1600 переходит в 1400.

---

## 13. Доминирующий лидер

В percentile-based системе лидер уже ограничен:

- У сильного игрока ExpectedScore высокий.
- За «ожидаемую победу» он получает небольшой прирост.
- За слабое выступление — заметный минус.

Рекомендация: не вводить специальные антилидерские штрафы сразу; запустить базовую систему, посмотреть данные, при необходимости добавить decay / top resistance позже.

---

## 14. Рекомендуемая первая версия

- **ActualScore:** `(1 - (place - 1) / (N - 1))^0.7`
- **ExpectedScore:** `1 - (expectedRank - 1) / (N - 1)`
- **DeltaLadder:** `K_tour * (ActualScore - ExpectedScore)`, по умолчанию K_tour = 30.
- **Bonus:** 0 на первой версии.

Итого: простая, понятная, честная percentile-based Ladder без фиксированных очков за места.

---

## 15. UI: как показывать игроку

После турнира игрок может видеть:

- Старый и новый Ladder.
- Delta (+/−).
- Итоговое место (например, 2nd out of 15).
- Ожидаемый финиш (например, around 6th out of 15).
- Relative result (например, «выступили выше ожиданий»).

Пример:

- Old Ladder: 1462
- New Ladder: 1475
- Delta: +13
- Result: 2nd out of 15
- Expected: around 6th out of 15

Формулы пользователю показывать не обязательно; система должна быть внутренне прозрачной и объяснимой короткими формулировками («рейтинг зависит от места относительно размера турнира и ожиданий»).

---

## 16. Разделение: турнирные очки vs Ladder

| Сущность                                | Назначение                                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Очки турнира** (placement + per_kill) | Определение места **внутри** турнира и отображение в таблице турнира. Не глобальный рейтинг. |
| **Ladder Rating**                       | Глобальный соревновательный рейтинг, обновляется после турнира по percentile-формуле.        |

Турнирные очки (scoring.placement, per_kill) используются только для ранжирования в рамках одного турнира и вывода таблицы. Глобальный рейтинг игрока — только Ladder (и отдельно DNA для аналитики).
